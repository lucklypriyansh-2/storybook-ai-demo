# m2.diff review

## iPhone Safari correctness

1. **Video is pinned muted; the promised "first-tap unmute + persist autoplay" never happens.** `src/screens/Feed.tsx:1544` always does `el.muted = true; el.play()…` and nothing reads/writes `settings.autoplay`. Without a tap-to-unmute handler + persisted toggle, every reel is silent forever on iOS. Severity: high. Fix: wire the slide (or feed container) `onPointerDown` once to `el.muted = false; api.updateSettings({ autoplay: true })` and read `!settings.autoplay` for the initial `muted` state; add a sticky mute button (promised top-right).

2. **`play().catch(()=>{})` swallows the iOS reject with no tap-to-play fallback.** `src/screens/Feed.tsx:1544`. The design doc explicitly calls this out. Severity: high. Fix: on reject, set a per-slide `needsTap` flag and render a centred ▶ overlay that calls `el.play()` from a trusted tap.

3. **`AudioContext` is created inside `pumpRenders` which runs from a `.then`, not a user gesture.** `src/store.tsx:1911` kicks `pump()` after `api.init().then(refresh).then(...)`, and on `onReels` events — both paths are outside any click handler. On iOS Safari the `AC` stays `suspended`, so recorded reels have **no music**, and `rec.start` on a stream with suspended-audio tracks can fail. Severity: high. Fix: only start `pumpRenders` from the actual user action that enqueued the job (the `createReel`/`remake` click in `Make.tsx` / `Remake.tsx`), and pass through the originating `MouseEvent.isTrusted` chain; or create the `AudioContext` in the click handler and hand it to `renderReel`.

4. **iOS Safari records fragmented MP4; many `<video src="blob:…">` players refuse it.** `src/render/renderReel.ts:1191` prefers `video/mp4;codecs=avc1…`; iOS Safari's `MediaRecorder` emits fMP4 without a `moov` at the head, which Safari's own `<video>` often won't seek/play when loaded from a Blob URL. Severity: high. Fix: either (a) prefer `video/webm` on WebKit and remux later, or (b) write the Blob to a temp file via `<a download>` + user re-opens, or (c) remux with mp4box.js before storing. At minimum, add a playability probe after render (`el.canPlayType(type)` + a 500ms `loadedmetadata` wait) and fall back to the poster + "Save to phone" if it fails.

5. **ParentGate keys cancel the hold on the slightest finger slide.** `src/screens/Gate.tsx:1627` binds `onPointerLeave={up}` and `onPointerCancel={up}`. On iOS a 2–3px drift during a 600ms hold fires `pointerleave` and resets `step`. Severity: high. Fix: drop `onPointerLeave`, use `el.setPointerCapture(e.pointerId)` on `pointerdown`, release on `pointerup`; only reset on `pointerup` fired at a different `n` than the one captured.

6. **MP4-from-IDB blob URLs are stored forever in `urls` map, and the previous version's URL is never revoked on remake.** `src/store.tsx:1901,1928-1930`. Every remake leaves one more orphan `URL.createObjectURL` + Blob pinned for the session. Severity: high (memory + iOS Safari evicts tabs well under 1 GB). Fix: track `url → objectURL` reverse map; when `videoSrc` is called and `url` differs from the cached one for that reel, `URL.revokeObjectURL(oldObjectUrl)` and delete. Also revoke all + clear on `deleteAll()`.

7. **Download-fallback `URL.createObjectURL(file)` is never revoked.** `src/screens/Family.tsx:1423`. Severity: med. Fix: `const u = URL.createObjectURL(file); a.href = u; … a.click(); setTimeout(() => URL.revokeObjectURL(u), 1000);`

8. **`AudioContext` is only `close()`d on the success path.** `src/render/renderReel.ts:1259-1280`. Any throw (image load, MediaRecorder error, `draw` exception) leaks the AC + its MediaStreamDestination for the life of the tab. Severity: high (leaked AC also keeps the page audible/unlockable). Fix: wrap the recording block in `try { … } finally { stream.getTracks().forEach(t => t.stop()); ac?.close().catch(()=>{}); }`.

9. **Rendering runs with the tab potentially backgrounded; `setTimeout(tick, 1000/FPS)` is throttled to ~1 Hz on iOS, canvas captureStream drops frames, and if the tab is suspended mid-record the job is wedged at `rendering`.** `src/render/renderReel.ts:1277`, `src/render/worker.ts`. Severity: med. Fix: use `requestAnimationFrame` instead of `setTimeout`; listen to `document.visibilitychange` — if hidden during `rec.state === 'recording'`, call `rec.stop()` and mark the job `failed` with a retry hint; add a watchdog that marks jobs `failed` if `rendering` for > 2× `duration_s`.

10. **IntersectionObserver callback never re-observes new slides added after mount.** `src/screens/Feed.tsx:1487-1492` observes `el.querySelectorAll('[data-i]')` once per `[total, tab]`. A `setReels` from realtime (`store.tsx:1911`) prepends a new reel without changing `total` relative to `tab` tick if the deps haven't re-run yet, leaving the new slide unobserved. Severity: med. Fix: observe in a `MutationObserver` or re-run effect on `s.reels.length`.

## Child-safety / privacy

11. **`family_share` consent defaults to `true`.** `src/data/local.ts:751` and `0001_init.sql:380`. The privacy policy published in this diff (`public/privacy/index.html:227-233`) explicitly promises "Making reels is the only required choice. Family sharing… are separate switches." Defaulting it on contradicts the policy and arguably violates COPPA 2026's "separate, not-integral" rule. Severity: high. Fix: default `family_share: false` in both places; also set `ai_training`, `marketing`, `publish_social` to `false` (already correct for the last three). Have `bootstrap_household` set it `false` and bump migration.

12. **`reels` RLS allows any authenticated member to INSERT directly, bypassing the `create` consent check.** `0001_init.sql:247-250` (`reels_all for all … with check(is_member)`). Only the RPCs (`create_reel`, `remake_reel`) check consents. A crafted client can POST to `/rest/v1/reels` and skip consent entirely. Severity: high. Fix: split `reels_all` into select-only for clients and move insert/update behind SECURITY DEFINER RPCs; or add a policy `with check (… and exists(select 1 from consents where household_id=reels.household_id and kind='create' and granted))`. Same reasoning for `reel_versions` and `publish_queue` insert policies.

13. **`rj_insert` lets any authenticated member enqueue unlimited render jobs.** `0001_init.sql:265-268`. No rate limit, no reel ownership tie. Severity: med. Fix: enforce in-policy that `reel_version_id` resolves to a row with `household_id = render_jobs.household_id`, and add a per-household rate limit via a check function or a daily counter table.

14. **`FirstMake` writes `localStorage` during render.** `src/App.tsx:673`. React may call the function body twice in Strict Mode / during concurrent rendering, and the side-effect bypasses React's lifecycle — also runs every time the route re-renders. Severity: low. Fix: move to `useEffect(() => localStorage.setItem(ONBOARD_KEY, '1'), [])` or set it in the `Make my child the star` click handler.

15. **`sessionStorage.getItem('pw.seen')` paywall trigger is per-tab — a child clearing the tab and relooving three reels will keep seeing the paywall.** `src/screens/Feed.tsx:1504`. Minor dark-pattern risk given the "child-first" framing. Severity: low. Fix: use the persisted store (`settings`) or `localStorage`.

## SQL 0002 / data layer

16. **`rename_kid` rewrites titles with `replace(title, v_old, v_name)` — substring match, not whole-word.** `supabase/migrations/0002_v1_additions.sql:2118-2122`. Renaming a kid called `Al` to `Alex` turns `"Alpha Moon"` into `"Alexpha Moon"`; renaming `A` to `B` corrupts everything. Severity: med. Fix: use `regexp_replace(title, '\m' || regexp_replace(v_old, '[\\.^$*+?()\[\]{}|]', '\\\&', 'g') || '\M', v_name, 'g')` (word boundaries) — or, better, re-derive book titles from the template + kid name instead of patching strings.

17. **`create_reel` sets every book page's `image` to `v_tmpl.cover`; `bootstrap_household` cycles through `template.scenes[].image`.** `0002_v1_additions.sql:2218-2231` vs `0001_init.sql:411-423`. New reels get a monotonous cover-on-every-page book while the seed reels don't — same template, different book. Severity: med. Fix: use the same `jsonb_agg(…jsonb_build_object('image', scenes -> ((idx-1) % greatest(…,1)) ->> 'image'))` expression from `0001`.

18. **`create_reel` resolves the household via "oldest `household_members` row" for the caller.** `0002_v1_additions.sql:2155-2160`. In v1 this works, but silently picks when the user is in ≥2 households — inconsistent with `remake_reel`/`queue_publish` which take the reel's `household_id`. Severity: med. Fix: accept `p_household uuid` with a `null` default that resolves to the sole membership; `raise` if the caller belongs to >1 household and `p_household is null`.

19. **`create_reel` doesn't check `settings.remake_enabled` (nor does `remake_reel`).** `0002_v1_additions.sql`, `0001_init.sql:435`. The toggle is purely cosmetic — a crafted client can call either RPC regardless. Severity: med. Fix: `remake_reel` should `raise` when `settings.remake_enabled = false`; `create_reel` probably fine to allow but document.

20. **`canonical()` key ordering may diverge from Postgres `jsonb::text` for non-ASCII or escape-heavy values.** `src/data/seed.ts:878-884`. The test only covers ASCII flat objects. Postgres `jsonb::text` does not escape `/`, uses `\uXXXX` for control chars, and may emit UTF-8 verbatim for the Starring Me state (which contains `…`, smart quotes, etc.). `JSON.stringify` escapes the same chars differently, so the browser hash for e.g. `{text:"Hi…"}` won't equal the SQL hash. Severity: med. Fix: compute the hash server-side only (drop the client hash field, let the RPC fill it from `v_state::text`), or use a shared canonical-JSON library on both sides.

21. **`SupabaseApi.onReels` polls every 8s indefinitely once any reel is non-ready, regardless of tab visibility.** `src/data/supabase.ts:955`. Burns battery + Supabase quota when a stuck `rendering` job is on the queue. Severity: med. Fix: wrap the interval with `if (document.visibilityState !== 'visible') return;` and clear/restart on `visibilitychange`.

22. **`SupabaseApi.init` ignores the anonymous sign-in error** then calls `bootstrap_household` which will fail with `not authenticated`, surfacing a confusing error. `src/data/supabase.ts:912`. Severity: low. Fix: await and validate `signInAnonymously()` before the RPC; also surface the real error to the user via `s.error`.

23. **`CONSENT_DEFAULTS` is seeded into `IndexedDB` and then revisited on every subsequent `init()` as "existing" — a later change to defaults never takes effect for returning users.** `src/data/local.ts:769-784`. Severity: low. Fix: merge seeded defaults with any missing kinds on `init`; same for `SETTINGS_DEFAULTS`.

24. **No test covers the Supabase RLS or the `create` consent bypass in finding #12.** `tests/data.test.ts` only exercises `LocalApi`. Severity: low. Fix: add an `rls.test.ts` (or SQL-level pgTAP) that signs in anonymously and asserts that a direct `insert into reels` with `consents.create=false` is rejected.

25. **`idb.ts` writes a `Blob` value into an IndexedDB object store on the key `video:<jobId>`** which iOS Safari supports, but the stored Blob is not re-materialised with a type on retrieval if the Blob was created from an empty chunk list; combined with #4 this means a failed MediaRecorder run can store a zero-type Blob and `videoBlob(...)` returns it anyway. `src/data/idb.ts:713`, `src/render/worker.ts:1306` only checks `blob.size`. Severity: low. Fix: in `markJob`, assert `blob.type.startsWith('video/')` before persisting, and in `videoSrc` re-type via `new Blob([b], { type: 'video/mp4' })` when `b.type === ''`.
